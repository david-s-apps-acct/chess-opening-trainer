# CLAUDE.md

## Project

Chess Opening Trainer: a browser app that pulls the user's Lichess studies (including private ones) and quizzes them on the correct next moves.

**SPEC.md is the source of truth for what the app does. Read it before any work and follow it.**

## Current phase

Building. The app is `index.html`; keep it in line with SPEC.md.

## Standing rules

- **License:** AGPL-3.0-or-later with a section 7(b) attribution term (`LICENSE`, `NOTICE.md`). Keep "Chess Opening Trainer by David Sharman" in the Help page, and add any new third-party part, with its license, to `NOTICE.md` and the Help credits.
- **American English (the user's decision, 18 November 2026):** use American spelling everywhere the user reads (the app, Help, messages), in SPEC.md, this file and code comments: color, gray, practice (also the verb: practiced, practicing), center, canceled, labeled, license. Existing code names with British spellings (`practisedAs`, `practisedLines`) may stay.
- **Writing for the user (the user's guideline):** assume users are intelligent and experienced at chess. Use as few words as possible on screen: brief labels, messages and hover hints, never long explanations. Longer explanations go on the Help page.
- The whole app is a single HTML file, `index.html`, opened from disk (`file://`) or from GitHub Pages. No server, no build step, no npm. Online, `sw.js` (the service worker) keeps it working offline: when a library, font or sound URL changes, update its file list and bump its `VERSION`.
- **The engine** is the exception: Stockfish 19 lite, single-threaded (`engine/stockfish-19-lite-single.js` and `.wasm`, from the npm package `stockfish` 19.0.1, unchanged; GPL-3.0, `engine/Copying.txt`), hosted in this repository (jsDelivr refuses that package for its size; the user chose GitHub over unpkg, 19 November 2026). It runs in workers, so not from `file://`. A new version means new files in `engine/`, `ENGINE` in `index.html`, `sw.js`'s `ENGINE_FILES` and `VERSION`, and NOTICE.md.
- Libraries load from the jsDelivr CDN via ES module imports:
  - chessops for PGN parsing and move validation
  - chessground for the board
  - Noto Sans (`@fontsource/noto-sans`) for the Lichess look, and Noto Sans Symbols 2 (`@fontsource/noto-sans-symbols-2`) for the piece symbols in move notation
  - Lichess's SFX sounds, via jsDelivr's GitHub route (`cdn.jsdelivr.net/gh/lichess-org/lila@<commit>/…`). Only use Lichess assets that COPYING.md marks as freely licensed; the default "standard" sounds are non-free.
- The page is always dark (Lichess dark theme); don't add a light mode.
- Call the Lichess API directly from the page.
- Browser storage:
  - localStorage for the Lichess token, the selection, stats and preferences (backups never include the token)
  - IndexedDB for cached study data and the downloaded Lichess data (move statistics and masters statistics; these are included in backups)

## Working with the user

- **Terminology (the user's standing rule):** use these terms consistently in everything the user sees (the app, Help, messages) and in SPEC.md:
  - **repertoire recall** (called move accuracy until 19 November 2026, then repertoire accuracy until 20 November: "accuracy" means engine closeness on Chess.com; the Studies page's Recall view follows it (the Recall slider did, until the sliders went on 20 November 2026); code names such as `accuracyAt` and the view key `errors` stay): how well you know a position of yours (in a chapter), as a percentage: the share of its last 10 attempts right first time (first move one of your study's moves, see `firstTryRight`; with Main lines, only the main move), unweighted (e.g. "75% recall (last 4 tries)"; for one attempt in the practice move list, 100% or 0%). Each position has two, from the same attempts (with Main lines, only the main move right, and without); Main lines practice uses the first, and everywhere else shows the second (`mainOnlyNow`, `mainOnlyFor`).
  - **line accuracy** is no longer used (removed 6 November 2026): a line is judged by its weakest position's repertoire recall (spaced repetition, the Show lines table's "Lowest repertoire recall"); the end of a line says "5 of 6 moves correct".
  - **position reached**: how many times a position was reached in rated Lichess games, always with `shortCount()`: "Reached 46 times (master games)" / "Reached 23k times (Lichess games)" in the Studies page's statistics tile (`renderStatsTile`), the column "Position reached (times)" in the positions table. (Hover boards show only the move since 19 November 2026.)
  - **errors are violet** everywhere (arrows and text), whatever kind; the kind is in the text, e.g. "(masters move)", "(alternative move)".
  - **No "pawns" on screen** (the user's rule, 20 November 2026): evaluations and losses are bare numbers, e.g. "Δ−0.5", "expected eval loss ≥ 0.5" (the code may say pawns).
  - Don't use "score" or a bare "accuracy" for these on screen. (Internal code names like `scoreClass` and the `score-100` classes may stay.)
  - **error** vs **mistake** (different concepts): an **error** is any move you play that isn't the one in your study (your preferred line), (Hint works only after a first try, so it's never the first move); errors cost repertoire recall ("Errors: …", "No errors.", "Error penalties"). **Mistake** is reserved for moves marked as a mistake (?), blunder (??) or dubious (?!) in a study (one definition everywhere: `isMistake()`), e.g. "marked as a mistake", "Prefer opponent's mistakes". Never call an error a mistake. Avoid "wrong" in labels; use "error".
  - **refutable move** (called punish move until 20 November 2026; the Refutations drill built 20 November; see SPEC.md, Refutable moves and refutation positions): a Lichess move in a study position that drops Stockfish's evaluation by the refutation threshold or more (the user's setting, default 1 pawn) compared with the engine's best move; the position after it is a **refutation position (Lichess)**, and your study's reply there **the refutation**; the future practice is **Refutations**. Don't use "punish". Defined without sides: whose to refute depends on the side the chapter is practiced from (`sidesOf`). Generally, say "your" or "opponent's" only where the side is known (during practice); on the Studies page, chapters may be practiced from either color. Not a "mistake", which stays the study's marking.
  - **Studies page**: the page with your studies and a chapter on a board (the header's Studies button, or the small board icon by the study's name during practice); it was called the Review page until 4 November 2026. Looking through a chapter on its board is still `review` in the code (`openReview`, `reviewBoard`); the page is `studies-screen`. Not "explore", which could be confused with Lichess's Opening Explorer (the move statistics).
  - **repertoire** (called group until 28 November 2026; "repertoire recall" keeps its name): a named set of chapters from your studies to practice (All is built in), chosen on the Practice page and edited on the Repertoires page (between Practice and Studies); `preset` in the code and stored data. Each chapter plays its **main color**, both colors, or only the other one: a white and a black button each (`colors`, `chapterColors`, `sidesOf`).
  - **Lichess move**: one played in 5% or more of the Lichess games in a position (`isLichessMove`, `LICHESS_SHARE`); a **masters move** is one played in 5% or more of the master games, where the position has 20 or more (`isMasterMove`, `MASTERS_SHARE`, `MASTERS_MIN_GAMES`).
  - **low recall** ("weak recall" for a few hours on 20 November 2026; less judgmental): a position of yours with repertoire recall below the **low recall threshold** (the user's setting since 27 November 2026, 50%, 75% (default), 90% or 100%, under Thresholds (Levels until 28 November 2026) in the Practice page's Positions tile: `settings.lowRecallLevel`, `isLowRecall`; fixed at 75% until then), the Studies page's violet dots (below 100% until 20 November 2026). See SPEC.md, Position measures.
  - **expected loss (you)** and **expected loss (Lichess)** ("your expected loss" and "Lichess expected loss" until 28 November 2026; code names such as `yourExpectedLoss` and `expectedLossAt` stay); expected loss (you): at a position of yours, the share-weighted Δ of your last 10 tries' first moves against the engine's best (`yourExpectedLoss`), shown as a Δ, e.g. "Δ−0.3".
  - **danger position** (critical position until 25 November 2026), two kinds (20 November 2026), each with its own threshold since 27 November 2026 (**your danger threshold** and the **Lichess danger threshold**; one danger threshold until then): **Danger position (Lichess)** (with the Lichess view), one whose **expected loss (Lichess)** is the Lichess danger threshold or more, and **Danger position (you)** (with the Recall view: `isYourDangerPosition`), one of yours whose expected loss (you) is your danger threshold or more (`settings.yourDangerLevel`). Say "(you)", not "(me)". The Lichess kind: one whose expected loss (Lichess) is the Lichess danger threshold or more (the user's setting, default 0.5 pawns, under Thresholds (Levels until 28 November 2026) in the Practice page's Positions tile: `settings.lichessDangerLevel`; spaced repetition's ×2 for danger uses this kind, at your move): the sum over its Lichess moves of each move's share × the pawns it drops Stockfish's evaluation below the engine's best move, for the side playing it (`expectedLossAt`, `dangerAt`; mate counts as 10 pawns). Rules use pawns, not winning chances (the user's decision). Never call those moves "mistakes". Don't say "critical" on screen.
  - **rarely reached** / **very rarely reached** (25 November 2026): a position your opponents lead you to in fewer than 1 game in 100 / 1 in 1,000 (Lichess), by the shares of their moves on the way, multiplied (`logReach`, `isRarelyReached`); the Positions tile's dropdown, "Exclude [none / under 1 in 100 / under 1 in 1,000]", can leave them out (`settings.practice.rare`, `RARE_CHOICES`, `withoutRare`); never lines.
  - **tries / statistics / data** (27 November 2026): your practice results are **tries** ("Reset tries"), the downloaded Lichess and masters data **statistics**, everything of yours in this browser **data** ("Saves your data to a file"). No "stats" on screen (code names such as `review-stats` may stay).
  - Name positions with the agreed convention (opening name plus the moves since; see SPEC.md, Naming positions), and show counts of games with `shortCount()`.

- When editing SPEC.md, record only what the user decided. If you add a detail or make an assumption they didn't state, add it and then point it out explicitly so they can accept or reject it.
- Ask before changing any decision already recorded in the spec.
- Ask one or two focused questions at a time, not long lists.

## Running

Open `index.html` in a browser. It needs internet access, for Lichess and the CDN.

For testing without a real token: serve the folder over localhost (the Browser pane blocks storage on `file://`), seed IndexedDB key `studies` in database `chess-opening-trainer`, or stub `window.fetch` for `/api/account` and `/export.pgn` (and `explorer.lichess.org` for move statistics).

**Tests:** `tests.html` (open over localhost) loads `index.html` without starting the app and checks the core logic (scoring, penalties, masters moves, position names, study parsing), plays whole practice lines through the app (wrong moves, alternatives, hints, ending early, single positions, the Practice page's chooser, spaced repetition, repertoires (presets), the Studies page (its list, hiding, the arrows switch), the engine (with a stand-in for Stockfish); saving and network are switched off from the start, so stored data is never touched), plus a recorded snapshot of how the test chapters become lines, trees and positions. It takes about 25 seconds. If results look stale, the local server may have stopped and the service worker is serving saved copies: restart it, and load `tests.html?v=N` to get past the browser's cache. Run it after any change to that logic or to practice; all checks should pass. After a deliberate change to the chapter structures, re-record the snapshot with `tests.html?record` and replace `EXPECTED_SNAPSHOT`.
