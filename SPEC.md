# Chess Opening Trainer — Spec

## Overview

A browser-based chess practice program. It pulls the user's studies from lichess.org and quizzes the user on the correct next moves.

## Lichess access

- Covers all of the user's studies, including private ones.
- Authenticates with a personal API token that the user generates once in Lichess account settings (Preferences → API access tokens).
- The token needs the `study:read` scope so private studies can be read.
- The user enters the token once; the browser remembers it (localStorage) so it isn't asked for again.
- The app should offer a way to clear or replace the stored token (on the Options page).
- A new token is checked with Lichess before it is saved; if Lichess rejects it, the app says so and doesn't store it.

### Fetching studies

- Studies are pulled from Lichess only when the user asks, via an "Update studies" button. The first visit (nothing cached yet) fetches automatically once the token is entered.
- Fetched studies are cached in the browser between visits. Use IndexedDB rather than localStorage, since a full export of many studies can exceed localStorage's ~5 MB limit.

## Selecting what to practice

The user chooses the practice set at any of these levels:

- **Individual chapters:** one or more specific chapters, possibly from different studies.
- **A whole study:** all chapters in one study.
- **A set of studies:** all chapters in several chosen studies.
- **Everything:** all chapters in all of the user's studies.

**Layout:** a checkbox list of the user's studies, each expandable to show its chapters with their own checkboxes.

- Studies are listed alphabetically; chapters keep their order within the study.
- **Opening name:** hovering over a chapter's name on the Studies page shows the opening from the chapter's Lichess PGN tags, e.g. "Italian Game: Classical Variation, Greco Gambit, Traditional Line (C54)": the `Opening` tag, then the `ECO` code in brackets. If only one of the tags is there, just that is shown; with neither, there's no hover text. It's shown in the app's own small pop-up (like the comment bubbles), which appears immediately (the user's choice: all the app's pop-ups appear immediately; the delay was 0.15 seconds, then 1 second), instead of the browser's standard tooltip, whose delay can't be set. (The tag describes the chapter as a whole, from its main line; variations deeper in the chapter may be other named openings.)
- Each study row shows its name, then in grey its number of chapters, e.g. "Ruy Lopez · 2 chapters".
- Each chapter row shows its name and side circle, then in grey its number of lines and, when there are any, its alternative moves, e.g. "Main line Chigorin ● · 5 lines · 2 alternative moves" ("1 line", "1 alternative move" when there's one; the alternative moves are left out when there are none; a chapter with no testable lines shows no counts). The line count is all the chapter's lines, whatever the "Opponent's moves" choice. Hovering over the alternative-move count explains it, in the same immediate pop-up as the opening names: "Other moves your study gives you at your turns, besides the main move. They aren't tested; only the main move counts as correct." (History: the counts were first on the study rows, as "4 chapters · 37 lines (+5 side variations)", then "· 5 alternative moves"; the user moved the line and alternative-move counts to the chapter rows.)
- An **alternative move** (called a "side variation" until the user asked for clearer wording) is another move for the user in the study, at one of the user's turns on a practiced line (e.g. 3. Bb5 where the main move is 3. Bc4). Each counts once, however many moves follow it; alternative moves inside other alternative moves aren't counted. They aren't practiced as lines (see Branches) and aren't included in the line count. The counts appear on chapter rows; study rows show only the number of chapters. The line count doesn't change with "Main line only"; the count at the top of the right-hand panel shows how many selected lines will actually be practiced.

- Ticking a study ticks all its chapters; unticking it unticks them all.
- If only some of a study's chapters are ticked, the study's checkbox shows a partial (indeterminate) state.
- Chapter rows are indented one tab (32px) to the right of their study's checkbox, on all screen sizes, so chapters clearly sit under their study. A chapter's two triangles sit under its study's ▸ and checkbox, so the chapter's checkbox stays one tab in.
- **A chapter's move tree:** each chapter row has its own ▸ button (like a study's) that opens the chapter's moves underneath it, indented one more step; ▾ closes them (hover: "Show moves" / "Hide moves"). Only the ▸ opens them; clicking the chapter's name still ticks or unticks it. A chapter with no testable lines (e.g. an unsupported variant) has no ▸ button, just a space.
  - The moves are shown as a tree, the way Lichess shows a study: the **main line** always shows, flowing along in Lichess style ("1. e4 e5 2. Nf3 Nc6 3. Bc4"). After a move that has alternatives, a small **+** button opens those variations underneath, each on its own indented row (with a thin line down the left), each in the same style and with its own + buttons; **−** closes them. The main line then continues on a new row ("3… Bc5 4. c3"). Variations start closed. Every move and variation in the study is included.
  - **All-variations triangle:** each chapter row has a second small triangle, just right of the moves triangle and left of the checkbox (so there are two side by side). It points right (▸) when the variations are closed and down (▾) when they're all open. ▸ opens every variation in the chapter at once, including variations inalternative moves and alternative moves, and also opens the chapter's moves if they're closed; ▾ closes all the variations (the moves stay shown). The individual + / − buttons keep working afterwards, and they don't change the triangle: after ▸, it stays pointing down even when single variations are closed with their −, until the triangle itself is clicked (which closes all of them). Likewise, opening every variation one by one doesn't turn it down. (At first it pointed down only while every variation was open; the user asked for it to change only when clicked.) Hover: "Show all variations" / "Hide all variations". A chapter without variations has an empty space there, so checkboxes stay lined up. (This replaced a "+ all / − all" button above the main line, at the user's request.)
  - All moves are in the standard text color (see Progress tracking for the highlighting of weak moves, and Comments and glyphs for glyph colors); move numbers are grey; **alternative moves at the user's moves** (never practiced), and everything after them, are in italics with no score. Move glyphs and comment bubbles appear as in the practice move list, following the annotations icon. Comment bubbles are the same soft blue as everywhere.
  - Every move has the small hover board (see Colored moves and the hover board). A side-variation move shows the position after it, like an opponent's move, labeled "Alternative move, not tested", with the move drawn as a white arrow, or a red arrow if the study marks it ?, ?? or ?!.
  - Open chapters and open variations stay open while the user moves around the app (like open studies), until the page is closed or reloaded.
  - History: this replaced a list of the chapter's lines (in study order, each with its colored moves, weakest score, evaluation and a "main line" label, with "Show all N lines" for chapters over 100 lines), at the user's request, together with the switch to per-position scores.
- An "All" checkbox at the top selects or clears everything.
- Each chapter and each study shows the user's score next to it, shown as just the percentage, e.g. "82%", with a one-sentence explanation in the hover pop-up (the same immediate pop-up as the opening names): "Accuracy over the last 10 attempts" (the user's wording, chosen after grading moved to points). (It said "82% right", then "82% correct moves", until the user asked for just the number with a hover explanation; the pop-up then said "How often you play your moves here correctly: the average over the 5 moves you've tried, each over its last 10 tries.") The figure is the average score of the moves the user has tried across all its lines (see Progress tracking), highlighted with the same ranges as the moves (see Progress tracking). Moves not tried yet don't count toward the average; if nothing has been tried, nothing is shown. A chapter with no testable lines (e.g. an unsupported variant, or no moves for the user) still says "no lines to test". (It used to show a miss rate per line.)

**Layout:** the list of studies and chapters is on the left, with the "All" checkbox at the top of the list, lined up with the studies' checkboxes. The selection controls are in a panel on the right: the count of chapters and lines, the "Start practice" button, then the options stacked one per line: the "Opponent's moves" radio buttons in an outlined box; the "Where lines start" radio buttons in an outlined box. (The "Show annotations" and "Show chapter names" checkboxes used to follow; they were replaced by icons on the practice page, which were later removed too.) Longer descriptions of these options show as hover tooltips. The panel stays in view while the list scrolls. On narrower screens (under about 800px) the panel moves above the list.

**Hidden studies:** a study the user no longer wants to see can be hidden; individual chapters can't (the user's choice).
- **The top eye:** a small eye icon at the right of the "All" row, after the favorites buttons. With a line through it (the normal state), hidden studies aren't in the list and study rows have no eye. Without the line, hidden studies appear in the list in grey (dimmed) and every study row gets its own eye. Hover: "Show hidden studies" / "Stop showing hidden studies". It's always clickable, even when nothing is hidden (it's also the way to hide studies), and isn't remembered: the list always opens with the line through it. There's no count of hidden studies.
- **Each study's eye** (only while the top eye is open), immediately to the right of the study name, before "· 2 chapters": a plain eye for a visible study (click to hide it: "Hid "Ruy Lopez". It won't be practiced."), an eye with a line through it for a hidden one (click to unhide it). So hiding a study is: open the top eye, click the study's eye, close the top eye.
- If every study is hidden (with the top eye closed), the list says "All your studies are hidden. Click the eye at the top to see them."
- **Excluded from practice:** hiding a study unticks all its chapters, and while it's hidden its checkboxes are disabled, so it's never practiced. "All" ticks only visible studies. Recall favorites skips chapters in hidden studies and says how many it skipped. Practice itself also ignores any chapter in a hidden study.
- Its stats are kept, so unhiding brings everything back as it was (its chapters stay unticked until ticked again). The automatic Lichess downloads still fetch data for hidden studies.
- Hidden studies are remembered between visits, included in backups, and survive Update studies (a study deleted on Lichess is dropped from the hidden list).
- History: first built with a "Show hidden (2)" text button and an eye that appeared at the end of a study row on hover; the user changed it to the top eye and per-study eyes after the name.

**Favorites:** two small buttons at the right of the "All" row. **Save favorites** (first called "Set as favorites") saves the chapters ticked now as the user's favorites (it's disabled when nothing is ticked; saving again replaces the previous favorites without asking). **Recall favorites** ticks exactly the favorite chapters again, replacing the current ticks, and leaves each study open or closed as it was (it used to open the studies containing favorites; the user asked for it not to). It's disabled until favorites have been saved. Favorites cover the chapter selection only, not other settings. Favorite chapters that no longer exist on Lichess are skipped, and the message says how many. Favorites are remembered between visits, included in backups, and mentioned on the Help page.

The last selection is remembered between visits (stored in the browser, like the token) and restored when the app opens.

### Chapters that can't be tested

- Chapters in a Lichess variant other than standard chess (e.g. Crazyhouse) show "variant not supported" and contribute no lines.
- Each chapter is capped at 5,000 lines, so a very large study can't freeze the page.

### Describe what to practice (removed)

- There used to be an optional "Describe what to practice" box on the Studies page: the user typed a request such as "all openings where I am white", and Claude (Haiku 4.5, via Anthropic's JavaScript SDK in the browser, with the user's own Anthropic API key) ticked the matching chapters. It was removed at the user's request (it was upkeep that other changes kept touching, and the app no longer stores an Anthropic key). Everything needed to rebuild it, including its full spec, the instructions sent to Claude and the code, is in `archive/natural-language-selection.md`, which the app never loads.
- On first opening after the change, the app deletes the stored Anthropic key and the natural-language setting from the browser. Older backups' natural-language setting is ignored.

### Opponent's moves

- An "Opponent's moves" box of radio buttons in the Studies page's right-hand panel (outlined, like "Where lines start") chooses how the opponent's replies are picked. It replaced the earlier "Main lines only" checkbox (a stored or backed-up "Main lines only" tick becomes "Main line only"). Remembered between visits and included in backups.
  1. **Main line only:** only each chapter's main line is practiced; the opponent always plays the chapter's main move. The toolbar count says e.g. "1 main line of 3". Lines are then chosen as usual (by the weakest move; see Choosing the next line).
  2. **Prefer most common moves:** at each point where the study has several opponent replies, a reply's chance is proportional to how many Lichess games played it (from the move statistics, which download automatically; each reply gets one extra game so unknown replies still come up occasionally). Positions without statistics treat all replies equally.
  3. **Prefer opponent's mistakes:** a reply marked in the study with ? (Mistake), ?? (Blunder) or ?! (Dubious move) is about 4 times as likely as an unmarked reply.
  4. **Prefer lines I miss** (default, the original behavior): every reply can come up; lines with moves the user often gets wrong come up more.
  5. **All moves equally:** at each point where the study has several opponent replies, each is equally likely; move results are ignored.
- In modes 2, 3 and 5 the preference **replaces** the move-results weighting when choosing lines. A line's chance is the product of the chances of its replies at each branch, so every chapter gets roughly the same share.
- The other rules still apply in every mode: "Where lines start" and no immediate repeats. Lines are always picked from all selected chapters together. (Because the same line can't come up twice in a row, a strongly preferred line can come up at most about half the time when only a few lines are available.)
- (There was also a "Next line" choice between "Any chapter" and "Finish the chapter" (every line of a chapter once before moving on, with a "Line 2 of 5 in this chapter" counter). It was removed as unnecessary alongside the Opponent's moves choices; to drill one chapter, tick just that chapter. A stored or backed-up next-line setting is ignored.)
- The Help page describes the five choices, including that "Prefer most common moves" treats replies without statistics as equally likely until their statistics have downloaded (so it works like "All moves equally" for them). No other on-screen note is shown for this.
- (There was also a "Weak lines only" checkbox with a miss-rate threshold; it was removed because "Prefer lines I miss" covers it. A stored or backed-up weak-lines setting is ignored.)

### Depth limit (removed)

- Lines are always practiced to their end. There used to be an optional per-chapter depth limit ("to move _x_", a number box next to each chapter, ending lines after the user's last move at or before move _x_). It was removed at the user's request and replaced by the **End line here** button (see End line here).
- **Stats carried over:** when the app first opens after the change (and when restoring an older backup that has depth limits), each shortened line's move results are copied to every full line that continues it; the moves up to the old limit are the same, so each move keeps its record. Where a full line already had results for a move, the copied ones are added after them, keeping the last 10. The shortened lines' own stats are then removed (unless the shortened line is itself a full line), and the stored limits are forgotten. Backups no longer include depth limits.

## Quiz

### Side to play

- The user plays the side the chapter's board is oriented to on Lichess (white or black); the app plays the other side's moves.
- The board is shown from the user's side.
- The practice panel doesn't say "You play white/black"; the board's orientation already shows it. (The Studies page shows the side with a small white or black circle immediately to the right of each chapter's name, with no wording; hovering over it shows "You play white" or "You play black". It used to say "you play white/black" with the circle in its own column. A chapter that can't be tested shows its reason, e.g. "variant not supported", instead of a circle. The Help page describes it as "You play the side at the bottom of the board".)
- Orientation comes from the `Orientation` PGN tag, so study exports must be requested with `orientation=true`. If the tag is missing, default to white.

### Branches

- **Opponent's move:** when the chapter has several variations at the opponent's move, which one is played is random, weighted toward lines with moves the user often gets wrong (see Choosing the next line).
- **User's move:** only the main-line move counts as correct, and lines always follow the main move at the user's turns (alternative moves at the user's move are never practiced as lines). When the user plays a move that the study has as an alternative move at that point:
  - **Marked ?, ?? or ?!:** the status says so, e.g. "Qh5?? is one of your alternative moves, marked as a blunder. The opponent replies 2… Nc6." The move and, if the variation has one, the opponent's reply from it are shown on the board; after about 2 seconds both are taken back and the status keeps just "Qh5?? is one of your alternative moves, marked as a blunder" (in red). (It used to say "Qh5?? is marked as a blunder in your study.", then "Try again, or press Hint." after the takeback; the user asked for consistent wording across the kinds of wrong move and no "Try again".) It counts as a wrong try, and the move is recorded as one of the user's wrong moves. Its study comment still appears only with Hint.
  - **Not marked:** a gentle message (not red), "Bc4 is one of your alternative moves" (it used to be "Bc4 is also in your study, but it isn't the main move. Try again."). The move is taken back straight away. It isn't a wrong try, but it costs 2 points (see Grading an attempt) and is recorded in the attempt; the line then counts as not clean ("Line complete." rather than "… No mistakes."). The message doesn't name the main move, so it doesn't give the answer away.
  - Any other wrong move gets a message in the same style (see Unlimited tries).
  - The Help page explains this.

### Making moves

- When the user moves a pawn to the last rank, a small picker asks which piece to promote to (queen, rook, bishop or knight).

### Comments and glyphs

- **Annotations are always shown** on the Practice page, during a line and after it: move glyphs, comment bubbles, the intro bubble and the wrong-move comment shown with Hint. (There used to be an annotations icon, a speech bubble in the practice panel's icon group, that hid them while a line was being played; the user removed it so they always show. Its stored setting and its entry in backups were dropped; older backups that contain it restore fine.)
- History: before the icon, this was a "Show annotations" checkbox (first labeled "Show comments"), first on the Options page and then in the Studies page's right-hand panel.
- Studies are always fetched with comments (`comments=true`), whatever the checkbox says. If the saved studies were fetched before comments were supported, the Options page says to click Update studies.
- **Speech bubbles** (the comments box below the board was replaced by these at the user's request):
  - In the move list, a move that has a study comment, or a position/observation glyph (such as ± or =), gets a small speech-bubble icon just after its notation, after any move-quality glyph (e.g. "e4 ! 💬"). It appears once the move is made (by the user, the app, or a reveal), including the moves set up before a partway start.
  - Hovering over a bubble (or tapping it on a touch screen, or focusing it with the keyboard) pops up the comment, in a box with the same soft blue background as the bubbles (#6f90b4) and white text, on the practice page and in the Studies page's move tree alike (other pop-ups, such as the opening name and the hover boards, keep the dark grey background): the move in bold, then any position/observation glyphs with their names (e.g. "3… Bc5 = Equal position"), then the comment text, e.g. "Giuoco Piano". Clicking a bubble doesn't step the move list to that move.
  - **Color:** all bubbles, the intro bubble too, are a soft, muted blue (#6f90b4; a paler #9bb8d6 on hover), so comments are noticeable but quiet. (They were grey with only the newest in blue, then Lichess's bright blue #3692e7 everywhere, until the user asked for a lighter shade; "lighter" was taken to mean softer, as elsewhere on this dark page.)
  - **The newest bubble** pops (a brief grow-and-glow) once when it first appears, so a new comment isn't missed.
  - **The chapter's introductory comment:** a bubble just after the chapter name at the top of the panel.
- Comment text is shown without the arrows, circles and evaluations Lichess embeds in comments.
- Only the glyph symbol is shown, not its name; hovering over a glyph (in the move list, the move tree or a hint message) shows its Lichess name in the same soft blue pop-up with white text as comments (it was first the browser's own tooltip); the bubble's pop-up names position and observation glyphs in full. The names are:
  - **Move quality:** !! Brilliant move, ! Good move, !? Interesting move, ?! Dubious move, ? Mistake, ?? Blunder, □ Only move, ⨀ Zugzwang.
  - **Position:** = Equal position, ∞ Unclear position, ⩲ White is slightly better, ⩱ Black is slightly better, ± White is better, ∓ Black is better, +− White is winning, −+ Black is winning.
  - **Observations:** N Novelty, ↑↑ Development, ↑ Initiative, → Attack, ⇆ Counterplay, ⊕ Time trouble, ∆ With the idea.
  - As on Lichess, a move with a move-quality glyph also has its text in that glyph's color, wherever moves are listed: the practice move list, the move tree and the end-of-line summary.
  - Move-quality glyphs use Lichess's exact colors (its default dark theme, checked against Lichess's source): ! Good move #629924 (olive green), !! Brilliant move #21c43a (bright green), !? Interesting move #f075e1 (pink), ?! Dubious move #53b2ea (blue), ? Mistake #e69d00 (orange), ?? Blunder #df5353 (red). (They were first set from memory; !, !! and !? were off and were corrected at the user's request.)
- When the user plays a wrong move, no comments are shown straight away. If the wrong move is an alternative move in the study with a comment or glyphs (e.g. a known mistake), they are shown in the status message when the user presses Hint (see Hint).

### Where lines start

- "Where lines start" is chosen at the top of the Studies (selection) page, in the panel under "Opponent's moves": three round radio buttons (one always chosen) grouped in an outlined box labeled "Where lines start": **From the start** (default), **Partway through**, or **Test single positions** (first labeled "Single positions"; the spec calls it Single positions for short). Each choice is on its own line, and each has its own hover tooltip describing just that choice. (For a while these were square checkboxes; they're radio buttons again so they read clearly as one choice.) It's remembered between visits, included in backups, and mentioned on the Help page. (It was first on the Options page, with a choice "A mix of both", which has been removed; a stored or backed-up "mix" setting is treated as "From the start".)
- A partway start is a random one of the user's moves, never the first, always leaving at least two of the user's moves to play (the one started at and at least one more). A line too short for that starts from the beginning.
- The position before that move is set up instantly, without sounds. The earlier moves appear in the move list (and can be stepped back through), their comments get bubbles, and the quiz starts with the user to move.
- The panel says where the line started (e.g. "Started partway, at move 7"), and the end-of-line summary repeats it (e.g. "Started partway, at 7. Bc4.").
- A partway play-through records only the moves actually played; the moves before the start aren't recorded.

### Single positions

- With "Single positions", each quiz is one move: the app picks a line from the selection (weighted as the "Opponent's moves" choice says, with its "Main line only" filter and no-immediate-repeats applied), then one of the user's moves in it **from move 5 on** (moves 1–4 are never tested there; the 5 is fixed, not a setting). Lines with none of the user's moves at move 5 or later aren't tested in this mode at all, and the line counts on the Studies and Practice pages leave them out while it's chosen. (At first any of the user's moves could be tested, the first move included.) With "Prefer lines I miss" (and "Main line only", which also uses move results), the move is picked by the same move weights as lines (see Choosing the next line), so moves the user often gets wrong come up more; with the other choices it's picked at random. It sets up the position before that move instantly and tests just that move; the rest of the line isn't played.
- The same position is never tested twice in a row when there's another to choose (positions shared by several lines count as the same position).
- The panel says e.g. "Single position, move 3". Tries, hints and comments work as usual.
- After a right answer (including after wrong tries or a hint), the status says "Correct. Next position…" and the next position follows after about a second. After a reveal, the app waits for a "Next position" button (or Enter) so the move can be studied.
- Each single position counts as one try of that move in its line (see Progress tracking). (Single positions weren't counted when stats were kept per line; they are now that results are kept per move.)
- With names hidden, the names (and intro comment) are shown after each answer.

### End line here

- An **End line here** button next to "Show correct move" on the practice page, available on the user's move (not in Single positions, which are one move anyway). It stops the current play-through at that point and shows the end-of-line summary straight away; the status says "Line ended early."
- It's **one-off**: the next time the line comes up, it's played in full. Nothing about the line is changed or remembered.
- The moves played so far count as usual. The move the user is on counts as wrong only if they had already made a wrong try or used a hint on it (then it's highlighted as missed in the move list); otherwise it isn't counted. The rest of the line isn't played or counted.
- The summary doesn't mention that the line was ended early (an "Ended early, before 7. Bc4." note was removed at the user's request).
- The Help page explains it under Practicing.

### Wrong moves

- The user can try as many times as they like; there's no limit and no automatic reveal. After a wrong try that isn't in the study, the piece goes back and the status says how popular the move is, in the same words as the alternative moves: "♕d3 is the #3 masters move but not your move" for a masters move (played in more than 10% of master games there; costs 2 points, so the message isn't red); otherwise "♕d3 is the #4 Lichess move but not your move" if it's among the Lichess games' saved moves there (the 10 most played plus the studies' own), or else "♕d3 is not your move" (both red). There's no "Try again, or press Hint". (It used to say "<move> is not the move. Try again, or press Hint.", or "…press Show correct move." once the hint had been used; the user changed it.)
- **Show correct move** (the Hint button's second stage, after the hint; see Hint), available on the user's move, shows the correct move with a green arrow and the status "The move is 1. e4. Play it on the board."; the player still has to make the move (the arrow stays until they do, and the button is disabled meanwhile; playing a different move is another wrong try, as usual). It counts the move as wrong. (It used to play the move automatically; the user asked for the player to make it.)
- After the line, a revealed move is highlighted as missed in the move list, and its hover board says "Wrong this time".
- (Earlier versions gave 3 tries, later a "Tries per move" setting of 1–5, with an automatic reveal after the last wrong try. That setting was removed in favour of unlimited tries plus the Show correct move button; it's no longer saved in backups, and older backups that contain it restore fine.)

### Study and chapter names on the Practice page

- The study and chapter names are **always shown** on the Practice page, during a line and after it. (There used to be an eye icon in the practice panel's icon group that hid them, and the opening, the ECO code and the intro bubble, while a line was being played, replacing them with the placeholders "Study", "Chapter", "Opening" and "ECO", to make the quiz harder; before that it was a "Show chapter names" checkbox on the Studies page. The user removed it so the names always show. Its stored setting and its entry in backups were dropped; older backups that contain it restore fine.)
- **The panel's heading** (above the move list) uses the same terms as the Weaknesses page, in two lines: the **study and chapter**, e.g. "My repertoire · Italian", as the main heading (bold, white, with the chapter's introductory comment as a bubble after it); then the **position reached**, named by the agreed convention (the deepest opening name, then the moves since; see Naming positions), e.g. "Italian Game: Giuoco Piano, 4. c3 ♘f6", in smaller grey text. The position line follows the line as it's played, so it always names the position on the board ("Starting position" before any move). (It used to be three lines: the study name, the chapter name, and the chapter's opening from its PGN tags, e.g. "Italian Game: Classical Variation, Greco Gambit, Traditional Line (C54)"; the user asked for the Weaknesses page's terms. Before that a fourth line showed the ECO code of the position reached, removed at the user's request, and the chapter name was once the heading with the study below.) On the idle Practice page, the selection count sits in the position line, in grey. While looking back at earlier moves (◀, the arrow keys or clicking a move), the position line names the position being viewed, and returns to the live one with it (at first it kept naming the live position; the user asked for this).
- The Help page explains that hovering over a glyph shows its name.

### Sounds

- Optional move sounds, using the "SFX" set from Lichess's code (by Enigmahack, AGPLv3+). Lichess's default "standard" sounds and Chess.com's sounds are not used: neither is licensed for reuse.
- A very small bell icon **just below the board, at its right edge**, turns sounds on and off with one click; it's the only sound control. When sounds are off, a diagonal line runs through the bell. Hovering shows what a click will do: "Turn sounds off" or "Turn sounds on". Sounds are off by default; the setting is remembered and included in backups. Turning them on plays a sample. ### Move popularity (Lichess database)

- **Automatic, in the background:** move statistics download by themselves, with no button: after **Update studies** (and when the studies are first fetched), and whenever the app opens, so a download that was interrupted resumes. Only positions without statistics are fetched; if nothing is missing, nothing is said. Update studies itself still finishes straight away. (History: at first they downloaded automatically after every refresh; then only with a "Refresh move frequency" button, later "Download move frequencies", in its own Options page box; the user then asked for automatic downloads again, without the button.) Move statistics download first, then Masters statistics.
- **Every position reached in the studies** is downloaded: every move and variation, including alternative moves' variations and each line's final position (earlier only positions where a move is played on the practiced lines were; the rest were added for the position count on the hover boards). For each, it's how often each move is played in the Lichess games database: all rated Lichess games, all ratings and time controls, not the Masters database. It uses Lichess's Opening Explorer (`explorer.lichess.org/lichess`), which requires the stored Lichess token (with no token, move statistics wait until one is saved; saving a token restarts the downloads).
- **What's saved for each position:** the Opening Explorer's answer **exactly as Lichess sends it** (`white`, `draws`, `black` for the games reaching the position; `moves`, a list with each move's `uci`, `san`, `averageRating` (the average rating of the players who made the move), `white`, `draws`, `black` and anything else Lichess includes; `topGames` and `recentGames`, empty because none are requested; and `opening` with its `eco` and `name`, or none for an unnamed position). The only thing dropped is moves beyond the **10 most played** (Lichess lists them most played first), except that any other move the studies have at that position (the user's main moves, opponent replies and alternative moves) is kept, so a rarer repertoire move still has its count and doesn't show 0%. Moves are matched ignoring + and #. Two fields are added: `v` (the format, 3) and `at` (when it was downloaded, used when merging a backup). A position no game reaches, found without asking Lichess, is saved in the same shape with zero games and `skipped`. The request still asks for up to 100 moves so the studies' rarer moves can be found. Nothing new is displayed yet; the position count and live ECO code (future improvements) will use it. (An interim version saved a reshaped copy, with moves keyed by name and `averageRating` renamed; the user asked for Lichess's own shape.)
- Positions saved before this (totals only) were treated as missing, so the next download fetched them all again with the details; until then their percentages still showed.
- Only positions that haven't been downloaded before are fetched; each position is fetched once even if it's in several lines. Results are saved in the browser (IndexedDB) and kept across visits.
- Requests are made one at a time, with no pause between them (there's no batch endpoint, so one request per position is the minimum). If Lichess answers "too many requests", the app waits a minute and carries on.
- **Most useful first:** positions in the selected chapters where the opponent has several replies come first (they drive "Prefer most common moves"), then the rest of the selected chapters, then everything else; within each group, shallower positions come before deeper ones.
- **Skipping positions nobody reaches:** if every known way into a position is a move that no Lichess game played (according to the statistics already downloaded for the position before it), the position is marked "no games" without a request. This is a close approximation: a different move order could occasionally reach such a position. The finished message says how many were skipped, e.g. "Move statistics downloaded for 1344 positions (380 skipped because no Lichess game reaches them)."
- A progress line in the Options page's Move frequency section (it was first under the header on every page) shows "Downloading move statistics: 120 of 850 positions", then "Move statistics downloaded for N positions." for a few seconds. Practice can continue while it runs; positions not downloaded yet have no percentages. If the connection fails, the line says so and that the rest downloads the next time the app opens or Update studies is pressed; if the token is rejected, it says to replace it on the Options page, after which the download continues. Closing the page stops the download; it resumes the next time the app opens.
- **Download order** (the same whatever is ticked, across all studies): (1) branch points (positions where the opponent has several replies), then (2) the rest of the chapters' main lines, then (3) everything else; within each group by move number (move 1 first). (It used to put the ticked chapters first.) A deep branch point may be fetched before the positions leading to it, so the "no game reaches it" shortcut can't always apply and a few extra requests are made; accepted.
- **Masters statistics:** for the same positions, the app also downloads Lichess's **Masters** database (over-the-board games between players rated 2200+ FIDE, from 1952): `explorer.lichess.org/masters?fen=…&moves=100&topGames=0`, also with the Lichess token. The answer is saved **exactly as Lichess sends it with the full move list** (masters positions usually have only a handful of moves), but **without the top master games** (none are requested, so `topGames` comes back empty), plus `v` (1) and `at`. It's stored separately from the Lichess games data (IndexedDB key `masters`), downloads automatically in the background after the Lichess games statistics (same order, same "no game reaches it" shortcut: "skipped because no master game reaches them"), has its own status and progress lines in the Move frequency box ("Masters statistics: 850 of 860 positions downloaded."), is included in backups and merged on restore (the newer copy of each position wins), and gets its own backup suggestion when complete. About 2 MB for ~1,800 positions. **Nothing displays it yet**; the user will decide how to use it.
- **Backup suggestion:** when a download finishes and every position has its statistics (not when nothing was missing, or when it stopped part-way), a banner suggests a backup: "Move statistics are complete. Save a backup so you won't need to download them again?" (or "Masters statistics are complete. …") with **Save backup** and **Not now** buttons.
- The Move frequency section of the Options page always shows how many positions have statistics, e.g. "Move statistics: 850 of 860 positions downloaded." It adds "(downloading now…)" while a download is running, updating as it goes, or "The rest downloads automatically after Update studies, or when you next open the app." when some are missing and nothing is downloading.
- The percentages appear only on the small hover boards (in the move tree, and in the practice move list once a line is over), never during the quiz. (The summary used to list them all, e.g. "In Lichess games: 1. e4 45% · 1… e5 48% · 2. Nf3 62%"; the user removed that list, since the hover boards show the same numbers.) A move's share is the number of games with that move divided by all games in that position. Shares below 1% show as "<1%"; a move not played in any game shows "0%"; a position with no games shows "no games"; a position not downloaded yet shows "–". Single positions have no summary, so they don't show percentages.
- The Help page explains the automatic downloads (under Getting started) and that hovering over a move in the summary shows its percentage (under Practicing).

### Choosing the next line

- The next line is picked at random from all lines in the user's selection, across all selected chapters.
- The pick is weighted so lines with moves the user often gets wrong come up more frequently. Each of the user's moves in a line has a weight of 1 + 4 × its wrong rate over its last 10 tries (see Progress tracking): a move always right has weight 1, one always wrong has weight 5.
- A move never tried counts as 50% wrong (weight 3), so new lines are introduced reasonably soon.
- A line's weight is its **weakest move's** weight (each move's score being that position's shared record) (the highest move weight), not the average, so one bad move can't hide among many good ones.
- This weighting applies with "Prefer lines I miss" and "Main line only"; the other Opponent's moves choices replace it.
- The exact numbers are a starting point and can be tuned.

### Spaced repetition (removed)

- There used to be spaced repetition: each clean play-through pushed a line's next review out to 1, 3, 7, 14 and then 30 days, due lines came first, the Studies page showed "3 due for review" and the Statistics page "review in 3 days". It was removed at the user's request when stats moved to move-level results. Stored review dates are no longer kept.

### No immediate repeats

- The same line is never picked twice in a row when any other line is available. This always applies.
- If the selection has only one line, it repeats.
- The last line is remembered until the page is closed or reloaded, so the rule also applies after going back to the selection screen and starting again.

## Progress tracking

- Results are recorded **per move, at each position in a chapter**, and kept between visits (stored in the browser, like the token and selection).
- A **line** is one path through a chapter from the start to the end of a variation, following the main line at every user move and any variation at opponent moves. It is identified by its study, chapter, and move sequence.
- **One record per position:** each of the user's moves has one record per point in the chapter's move tree, identified by the chapter plus the moves leading to and including it. Every line that passes through that point shares the record, so getting 3. Bc4 right in one line counts for every line that continues from it. The same board position in a **different chapter**, or reached by a **different move order**, keeps its own record (the user may play differently in different contexts). This also applies to the times recorded (when each position was last tried, and line times). The user confirmed that history is **not** to be merged across chapters.
- History: at first, records were kept per line (the same move in two lines, even with the same moves before it, was recorded separately). The user asked to drop line scoring and keep only the scoring of moves at a position, which also gives the move tree one score per move. Existing per-line records were merged into the position records when the app was next opened: each line's results for a move joined that position's record, keeping the most recent 10 (older backups are converted the same way when restored).
- For each of the user's moves, the app keeps its **last 10 attempts**. Older attempts drop off. Each attempt saves:
  - **what the user did, in order:** every move tried (wrong moves, alternative moves marked or not, and the correct move at the end if it was played) and the moments the Hint and Show correct move buttons were pressed, e.g. `["d4", "Bc4", "hint", "show", "e4"]`; a correct first try is just `["e4"]`; an attempt cut short by End line here has no correct move at the end;
  - its **points**, 0–10 (see Grading an attempt).
- **Grading an attempt:** each attempt starts at **10 points**; finding the correct move on the first try keeps all 10. Every step before the correct move costs points, each time it happens (repeats cost again):
  - an **unmarked alternative move** from the study: **−2** by default (the **Alternative move** penalty);
  - a **masters move**: **−2** by default (the **Masters move** penalty). A masters move is one **within the top N** master moves in that position (N chosen on the Options page, top 1 to top 5, default **top 5**; moves played equally often share a rank, so a tie at N counts) **and** played in **10% or more** of master games there (from the Masters statistics). E.g. with top 5, if only 3 moves reach 10%, only those 3 count; a 5th move at 6% doesn't. A move that is both an unmarked alternative and a masters move costs the alternative's penalty, once. (It was "more than 10%" with no top-N limit until the user made it configurable.)
  - an **alternative marked ?!, ? or ??**: **−5** by default (the **Error** penalty; the study's marking wins over a masters move);
  - **any other wrong move**: **−5** by default (the **Error** penalty). (Errors were −10 until the user lowered them to −5; the hint stayed at −10.)
  - the **Hint**: **−10** by default (the **Hint** penalty); **Show correct move** costs the same again, so with the default the score is already 0.
  - **The penalties are set on the Options page**, in a card titled **"Mistake penalties"**: one drop-down each for Alternative move, Masters move, Error (which covers marked alternatives too) and Hint (which covers Show correct move), each **0%, 10% … 100%** of an attempt's score (1 point = 10%), defaults 20%, 20%, 50%, 100%; and a drop-down **"What counts as a masters move"**, Top 1 … Top 5, default Top 5, between Masters move and Error. Each drop-down has a short grey explanation after its name. Changing any of them **re-scores all saved attempts straight away**, so the highlighting, the Studies page percentages and the Weaknesses page reflect it at once. They're remembered and included in backups. *Claude's choices, for the user to accept or reject:* the card is the first on the Options page; a line in progress keeps the points already worked out for the moves played so far in it.
  - The floor is **0**. So an attempt scores 10, 8, 6 or 4 when the only slips were reasonable moves, 5 after one real mistake, 0 after two, and 0 after the hint. If a position's masters statistics haven't downloaded yet, no move there counts as a master move.
- **Saved points, refreshed each session:** an attempt's points are worked out when it's recorded and saved with it, so pages only read saved numbers. When the app opens (and after restoring a backup), every saved attempt is scored again from what was done, with the current rules and data (e.g. masters statistics downloaded since, or alternatives added in Update studies), and saved. A score can therefore change between sessions, never during one.
- **When each line was played:** for each line, the app saves when it was played through to its end, the **last 10 times** (oldest dropped), for spaced repetition to be added later. A line's time is the time of the **last move attempted** in it; move attempts themselves don't each get a time (the user's choice). A line counts as played through only when it's played all the way from move 1 to the end; a line started partway, a line ended early with End line here, and Test single positions don't record a time for the line, only for the moves played (see When each position was last tried). (At first a partway line that reached its end counted too; the user changed it, as simpler.) Nothing is recorded for plays before this was added. The times are dropped for lines that no longer exist after Update studies, and they're included in backups (a backup without them restores fine). Nothing shows them yet.
- **When each position was last tried:** for each of the user's moves (each position, keyed like the stats), the app also saves the time it was **last attempted**, a single time, replaced each time, for testing individual positions later (the user asked for it after first deciding against times per attempt). It's recorded in every mode, whenever an attempt is recorded: lines played to the end, lines ended early (for the move being tried), partway lines and Test single positions. Nothing is recorded for attempts before this was added. Dropped for moves no longer in the studies after Update studies; included in backups (a backup without them restores fine). Nothing shows it yet.
- The Help page explains both (Your statistics, "When lines and positions were last practiced"): a line counts only when played all the way through, from move 1 to the end; a position counts whenever it's attempted, so it can be more recent than any line through it (the user asked for this to be in the Help).
- A move's **score** is the **weighted** average points of its last 10 attempts (or however many there are), as a percentage of 10. Recent attempts count more: the most recent is weighted 100%, the one before 90%, then 80% … down to 10% for the 10th most recent; the score is Σ(weight × points) ÷ Σ(weights). E.g. attempts of 0, 8, 10, 10 (oldest to newest): (10×1.0 + 10×0.9 + 8×0.8 + 0×0.7) ÷ 3.4 ≈ 7.5, i.e. 75% (a plain average would be 70%). The hover board's "Average 7.5 of 10" is this weighted average. (It was a plain average until the user asked for recent attempts to count more.) Percentages are rounded down, so a score just under a boundary keeps the lower color. The score drives everything as before: the highlighting, the Studies page percentages, and the weights for "Prefer lines I miss" and Test single positions (a move's wrong rate being 1 − score).
- History: at first each attempt was just right (first try, no hint) or wrong, saved as 1 or as the list of wrong moves played, and unmarked alternatives weren't counted. The user asked for this points system. Existing results were converted when the app next opened: right became `[correct move]` with 10 points; wrong became the saved wrong moves (or `["hint"]` for an attempt that was only a hint or Show correct move), scored with the new rules (a hint used after a wrong move wasn't recorded then, so those may score a little high until they age out).
- **Highlighting** (a chapter's move tree and the Studies page scores): the move text stays in the normal color, and only moves that need work are highlighted, with a **violet background** whose strength shows how weak the move is: 100% plain (no highlight); 90–99% a faint tint; 70–89% a medium tint; 69% or less a strong tint. Every move's text, the user's (right, weak or never tried) and the opponent's, is in the standard Lichess text color, like any move on Lichess; the only exception is a move the study marks with a move-quality glyph (! ? !! ?? !? ?! □), whose text takes the glyph's Lichess color. (For a while right moves were brighter white, untried moves grey with a dotted underline and the opponent's moves grey; the user asked for the standard color throughout.)
- Why violet: on Lichess and Chess.com, red and amber on a move mean the move is bad, but here the highlighted move is the correct one that the user keeps missing. Violet isn't used by chess sites for move quality, so the two meanings don't clash. (The first version colored the move text white / green / amber / red; the user asked for a different approach and chose background highlighting of weak moves only.) The small board's arrows keep green for the correct move and red for wrong moves, since there those colors do mean right and wrong.
- A play-through of a line records a try for each of the user's moves actually played; a partway start records only the moves from the start point on, and a single position records one try of that move.
- A line left unfinished (the user goes to another page and the line is dropped, or never finished) is not recorded.
- The earlier per-line stats (plays and misses per line, plus review dates) were cleared once when this was built, since they don't say which move was missed. Older backups with those stats restore their settings, but their stats are left out (the message says so).
- After a refresh from Lichess, records for positions no longer in any line are dropped; the rest keep their records.
- The Studies page's average for a chapter or study counts each tried position once.

## Technology

- **Version control:** the project folder is a local git repository (no GitHub or upload), set up at the user's request; each agreed change can be committed as a snapshot and undone by going back to an earlier one. The first commit recorded the app, spec, project notes and the natural-language archive.

- **Delivery:** a single HTML file (`trainer.html`) on the user's computer, opened directly in the browser (`file://`). No server, no build step.
- **Lichess API:** called directly from the page; the Lichess API allows cross-origin browser requests.
- **Libraries:** chessops and chessground (JS and CSS) are loaded from the jsDelivr CDN via ES module imports. The app needs internet to reach Lichess anyway, so this adds no new requirement.
- **PGN parsing:** use [chessops](https://github.com/niklasf/chessops), the library Lichess itself uses. Its `chessops/pgn` module parses study PGN into a move tree that keeps all variations, and its move logic validates the user's moves.
- **Font:** Noto Sans from jsDelivr (`@fontsource/noto-sans`), plus Noto Sans Symbols 2 (`@fontsource/noto-sans-symbols-2`) for the chess piece symbols; only the subset containing the symbols is downloaded.
- **Move statistics:** Lichess Opening Explorer API (`explorer.lichess.org/lichess`), called from the page with the Lichess token.
- **Sounds:** Lichess's SFX move and capture sounds, served by jsDelivr from the `lichess-org/lila` GitHub repository at a pinned commit.
- **Board UI:** use [chessground](https://github.com/lichess-org/chessground), Lichess's board library, which pairs with chessops. The user makes moves by dragging or clicking pieces on it. It uses Lichess's default look (brown board, cburnett pieces); no other board or piece styles are offered.

## Possible future improvements

Ideas agreed or mentioned along the way that haven't been built yet:

- **Ideas from research into what 1400+ and 1800+ players need** (30 September 2026; suggested by Claude after the user asked; not yet discussed in detail, so each needs the user's decisions before building). In Claude's suggested order of value:
  1. **Your Lichess games compared with your repertoire** (both levels; highest value): fetch the user's recent Lichess games with the stored token and, for each, find where the user left the repertoire (a forgotten move: those come up first in practice) and where the opponent left it (a gap in the studies, listed by how often it actually happened).
  2. **Spaced repetition, "due today"** (both levels): using the per-position last-tried times already recorded, give each move a review interval that grows when it's answered well and resets when it isn't (Chessable's intervals run roughly 4 hours, 1 day, 3 days, 1 week, 2 weeks, 1 month, 3 months, 6 months), and a "Due moves" practice mode that tests only what's about to be forgotten.
  3. **Move statistics for the user's rating band** (both levels, especially 1400+): download the Lichess move statistics filtered by rating (e.g. 1400–2000) and time control instead of all ratings, so "Prefer most common moves", the Weaknesses page and the hover board's ranks and shares reflect what the user's own opponents play.
  4. **Gap finder** (mainly 1800+): for each position in the studies where it's the opponent's move, list the replies played at least about 5% of the time (at the user's level) that the study doesn't answer, plus a coverage percentage per chapter; perhaps a second table on the Weaknesses page.
  5. **Punishing common mistakes** (mainly 1400+): find opponent replies that are popular at the user's level but score badly for the side playing them (from the win/draw/loss figures Lichess sends), and flag those the study doesn't answer.
  6. **Model games for each line** (both levels): at the end of a line, show two or three master games that reached that position (the Masters database's top games, not requested today), with links to play through them on Lichess, to learn the plans behind the moves.
  7. **Transposition awareness** (mainly 1800+): when the position reached also appears in another chapter or by another move order, say so (e.g. "Same position as Italian, after 4. c3"); information only, the histories stay separate.
  8. **Speed of recall** (both levels, for blitz and rapid): record how long each answer takes and treat slow correct answers as weaker.
  - Claude's recommendation: start with 1 and 2, and do 3 early since it's a small change that improves several existing features.
- Selecting individual lines (not just whole chapters) from a natural-language request such as "lines longer than 10 moves"; this needs a line-level filter. Only relevant if natural-language selection is ever brought back (it was removed; see Describe what to practice).
- **Offline copy:** a separate `trainer-offline.html` that runs without an internet connection, for practicing with saved studies, stats, move frequencies (anything that talks to Lichess or Anthropic would still need a connection: Update studies, the two download buttons, fetching an evaluation at the end of a line, checking a token, natural-language selection).

A folder of files beside the page wouldn't work, because browsers block scripts loaded from neighbouring files on `file://`.
  - The file would grow from about 144 KB to roughly 1–2 MB.
  - `trainer.html` stays the file that's edited; a small script generates the offline copy whenever a fresh one is wanted (this keeps the "no build step" rule for the app itself). The offline copy would also be a fully self-contained backup that keeps working if jsDelivr or the pinned library versions ever disappear.
  - Discussed and deferred by the user ("not yet").

## Ideas for a separate app

Not part of this app; recorded so they aren't lost.

- **AI game reviewer that explains moves** (30 September 2026): an app to evaluate a whole game, combining a chess engine (Stockfish or Lichess's cloud evaluations) with an AI (Claude) that explains *why* a position is better for one side and why a move is good or bad, in human terms (pawn structure, king safety, piece activity, plans), rather than only giving numbers and engine lines.
  - How it would work (Claude's outline): the engine supplies the facts (evaluation, best moves, the refutation of a mistake); code works out the concrete board features (material, pawn structure, king safety, open files, loose pieces); the AI turns these into an explanation; and the engine checks each claim (e.g. that a stated threat really works), discarding explanations that don't hold up. Where an evaluation rests on deep tactics with no human-sized reason, it should say so instead of inventing one, and small differences between good moves aren't worth explaining.
  - Why separate (the user's decision): explanations matter most at a game's turning points, mostly in the middlegame, rather than in prepared openings, whose ideas the study comments already cover; a game review has a natural shape (find the turning points, explain only those), which also keeps the number and cost of AI questions low; and it keeps this app free of an API key, an engine download and per-question costs.
  - A possible link: finding where a game left the repertoire is close to this app's future idea of comparing your Lichess games with your repertoire, so the two could share that step.
